🔍 Drunken Bishop Algorithm là gì?

📖 Khái niệm cơ bản

Drunken Bishop Algorithm là một thuật toán được sử dụng để tạo ra ASCII art fingerprint từ dữ liệu hash, giúp con người dễ dàng nhận diện và so sánh các fingerprint.

🎯 Mục đích chính:

  • Visualization: Chuyển đổi hash thành hình ảnh ASCII dễ nhận diện
  • Security: Giúp phát hiện man-in-the-middle attacks
  • User Experience: Tạo fingerprint dễ nhớ hơn so với hex strings
  • Quick Comparison: So sánh nhanh các SSH keys hoặc certificates

🔬 Nguồn gốc:

Thuật toán này được giới thiệu trong OpenSSH và lấy cảm hứng từ "random walk" - giống như một người say rượu đi bộ ngẫu nhiên trên một lưới ô vuông.

Giải thích:

  • S: Điểm bắt đầu (Start)
  • E: Điểm kết thúc (End)
  • . o + = * B O X #: Mức độ ghé thăm (0-8+)
  • Càng nhiều ký tự đặc biệt = càng được ghé thăm nhiều

⚙️ Các bước cơ bản của thuật toán:

Bước 1: Khởi tạo lưới 17×9 với tất cả giá trị = 0
Bước 2: Bắt đầu từ vị trí trung tâm (8, 4)
Bước 3: Đọc từng byte của hash, mỗi byte cho 4 bước di chuyển
Bước 4: Di chuyển theo 2 bit: 00=↖, 01=↗, 10=↙, 11=↘
Bước 5: Tăng giá trị ô hiện tại lên 1 (max = 15)
Bước 6: Chuyển đổi giá trị thành ký tự ASCII

📐 Lý thuyết toán học

🧮 Random Walk Theory

Drunken Bishop dựa trên Random Walk - một quá trình ngẫu nhiên mô tả đường đi của một đối tượng di chuyển ngẫu nhiên.

$$P(X_{n+1} = j | X_n = i) = p_{ij}$$

Xác suất chuyển từ trạng thái $i$ sang $j$

🎯 Trong Drunken Bishop:

  • State Space: Lưới 17×9 = 153 vị trí
  • Transition: 4 hướng di chuyển có thể
  • Probability: Phụ thuộc vào 2 bit của hash
  • Boundary: Không thể di chuyển ra ngoài lưới

🔢 Bit Encoding:

$$\begin{align} 00_2 &\rightarrow \text{↖ (Northwest)} \\ 01_2 &\rightarrow \text{↗ (Northeast)} \\ 10_2 &\rightarrow \text{↙ (Southwest)} \\ 11_2 &\rightarrow \text{↘ (Southeast)} \end{align}$$

📊 Phân bố xác suất

Do tính chất random walk, các ô ở trung tâm có xu hướng được ghé thăm nhiều hơn:

$$\text{Visit Count}(x,y) \sim \text{Distance from center}^{-1}$$

⚡ Complexity Analysis

Time Complexity: $\O(n)$ where $n$ is hash length in bytes

Space Complexity: $\O(1)$ - Fixed 17×9 grid

Hash Processing: $\O(4n)$ steps for $n$ bytes

📈 Performance Characteristics:

  • Deterministic: Cùng input luôn cho cùng output
  • Fast: Chỉ cần một lần duyệt qua hash
  • Memory Efficient: Grid nhỏ cố định
  • Collision Resistant: Khác biệt nhỏ trong hash → khác biệt lớn trong pattern

📋 Algorithm Steps:

1. Initialize 17×9 grid with zeros
2. Start at center position (8, 4)
3. Read next byte from hash
4. Extract 2-bit pairs for movement direction
5. Move bishop according to bit pattern
6. Increment visit count at current position
7. Repeat until all hash bytes processed
8. Convert visit counts to ASCII characters

💻 Cài đặt thuật toán

🔧 JavaScript Implementation


class DrunkenBishop {
    constructor() {
        this.GRID_WIDTH = 17;
        this.GRID_HEIGHT = 9;
        this.grid = Array(this.GRID_HEIGHT).fill()
            .map(() => Array(this.GRID_WIDTH).fill(0));
        this.x = Math.floor(this.GRID_WIDTH / 2);  // Start at center
        this.y = Math.floor(this.GRID_HEIGHT / 2);
        this.startX = this.x;
        this.startY = this.y;
    }

    // Move direction based on 2-bit pattern
    move(bits) {
        const dx = (bits & 1) ? 1 : -1;  // Right if bit 0 set
        const dy = (bits & 2) ? 1 : -1;  // Down if bit 1 set
        
        // Boundary checking
        this.x = Math.max(0, Math.min(this.GRID_WIDTH - 1, this.x + dx));
        this.y = Math.max(0, Math.min(this.GRID_HEIGHT - 1, this.y + dy));
        
        // Increment visit count (max 15)
        this.grid[this.y][this.x] = Math.min(15, this.grid[this.y][this.x] + 1);
    }

    // Process hash string
    processHash(hashHex) {
        const bytes = this.hexToBytes(hashHex);
        
        for (let byte of bytes) {
            // Each byte gives us 4 moves (2 bits each)
            for (let i = 0; i < 4; i++) {
                const bits = (byte >> (i * 2)) & 3;
                this.move(bits);
            }
        }
    }

    // Convert to ASCII art
    toASCII() {
        const chars = " .o+=*BOX@%&#/^SE";
        let result = "+--[HASH]----+\n";
        
        for (let y = 0; y < this.GRID_HEIGHT; y++) {
            result += "|";
            for (let x = 0; x < this.GRID_WIDTH; x++) {
                if (x === this.startX && y === this.startY) {
                    result += "S";  // Start position
                } else if (x === this.x && y === this.y) {
                    result += "E";  // End position
                } else {
                    result += chars[Math.min(this.grid[y][x], chars.length - 1)];
                }
            }
            result += "|\n";
        }
        result += "+-----------------+";
        return result;
    }

    hexToBytes(hex) {
        const bytes = [];
        for (let i = 0; i < hex.length; i += 2) {
            bytes.push(parseInt(hex.substr(i, 2), 16));
        }
        return bytes;
    }
}

// Usage example
const bishop = new DrunkenBishop();
bishop.processHash("9d5b8b89a5c64b1a2f3e8c7d");
console.log(bishop.toASCII());

🔍 Code Walkthrough

1. Grid Initialization:

Tạo lưới 17×9 với tất cả giá trị ban đầu = 0. Kích thước này được chọn để tạo ra ASCII art có tỷ lệ hợp lý.

2. Movement Logic:

$$\text{direction} = \begin{cases} \text{↖} & \text{if bits = 00} \\ \text{↗} & \text{if bits = 01} \\ \text{↙} & \text{if bits = 10} \\ \text{↘} & \text{if bits = 11} \end{cases}$$

3. Boundary Handling:

Khi bishop cố gắng di chuyển ra ngoài lưới, vị trí được giữ ở biên. Điều này tạo ra hiệu ứng "wall collision".

4. Visit Counting:

Mỗi lần ghé thăm một ô, giá trị tăng lên 1. Giá trị tối đa là 15 để tránh overflow và đảm bảo character mapping hoạt động đúng.

⚖️ Ưu nhược điểm

✅ Ưu điểm:

  • Human-friendly: Dễ nhận diện visual patterns
  • Fast: $\O(n)$ time complexity
  • Deterministic: Cùng input → cùng output
  • Compact: Visualization chỉ 17×9 characters
  • Secure: Hard to forge specific patterns

❌ Nhược điểm:

  • Information Loss: Nhiều hashes có thể có pattern giống nhau
  • Not Cryptographically Secure: Chỉ để visualization
  • Limited Entropy: 17×9 grid có entropy hạn chế
  • Visual Similarity: Một số patterns có thể nhầm lẫn

🔬 Security Considerations

Quan trọng: Drunken Bishop chỉ để visualization, không thay thế cryptographic verification!

🛡️ Best Practices:

  • Luôn verify cả hex fingerprint và visual pattern
  • Sử dụng kết hợp với other authentication methods
  • Không rely hoàn toàn vào visual similarity
  • Regular key rotation và verification
